# Google Sheet Work Board

구글시트 한 장을 **업무 칸반 보드 + 캘린더 + 요약 차트**로 보여주는 단일 HTML 대시보드입니다.
빌드 도구·서버·외부 라이브러리 없이, 파일 하나를 브라우저로 열면 끝입니다.

## 특징

- **칸반 보드** — 카드에 태스크명, 최신 진행 메모, 마지막 업데이트 경과일이 클릭 없이 표시됩니다.
  카드를 누르면 오른쪽에서 상세 패널이 열립니다.
- **무소식 감지** — 진행 메모의 `[8/13]` 형식 날짜를 읽어, 7일 이상 주황 / 14일 이상 빨강 배지를 붙입니다.
- **캘린더** — 처리예정일자 · 처리일자 · 요청 일자 · 업데이트 기록 중 기준을 골라 월별로 봅니다.
  데이터가 가장 많은 기준을 자동 선택합니다.
- **요약 · 표** — 상태별 / 분류별 / 우선순위 / 마감 위험 차트. 막대를 클릭하면 해당 목록이 즉시 펼쳐집니다.
- **루틴 업무 관리** — `반복 주기`(M열)와 `최근 수행일`(N열)만 적으면 다음 예정일을 자동 계산해
  **지연 / 오늘 / 이번 주 / 예정 / 미실행** 으로 분류하고, 다음 14일 부하까지 보여줍니다.
- **상태값 자동 반영** — 상태 목록을 코드에 고정하지 않습니다. 시트 드롭다운에 새 상태를 추가하면
  KPI · 보드 열 · 필터 · 캘린더 범례에 자동으로 나타나고 `NEW` 배지가 붙습니다.
- 라이트 / 다크 모드, 색약 대응(색 + 아이콘 + 라벨 병행)

## 사용법

1. `dashboard.html` 을 내려받습니다.
2. 구글시트를 **파일 → 공유 → 링크가 있는 모든 사용자(보기)** 로 설정합니다.
3. 시트 URL에서 ID를 복사합니다.
   `https://docs.google.com/spreadsheets/d/` **`여기가 ID`** `/edit`
4. 파일을 열 때 URL 뒤에 ID를 붙입니다.

   ```
   dashboard.html?sheet=1AbCdEfGhIjKlMnOpQrStUvWxYz
   ```

ID를 붙이지 않으면 **데모 데이터**로 열립니다. 먼저 데모로 화면을 확인해 보세요.

> 시트 ID는 코드에 하드코딩하지 않습니다. 저장소에 업무 데이터가 남지 않도록 의도한 구조입니다.

## 시트 형식

1행은 헤더, 2행부터 데이터입니다. **열 순서(A~L)가 기준**이며 헤더 텍스트는 무엇이든 상관없습니다.

| 열 | 내용 | 필수 |
|---|---|---|
| A | 요청 분류 | |
| B | ID | |
| C | 요청자 | |
| D | 요청 일자 | |
| E | **태스크** | ✅ |
| F | 상세 내용 | |
| G | 우선순위 (`상`/`곧`/`하`) | |
| H | 상태 | 권장 |
| I | 처리예정일자 | 권장 |
| J | 처리일자 | |
| K | 진행 현황 및 변동 사항 | 권장 |
| L | 피드백 | |
| M | 반복 주기 (루틴 업무) | 루틴만 |
| N | 최근 수행일 (루틴 업무) | 루틴만 |

빈 칸은 `미분류` · `상태 미기입` · `미지정` · `미입력` 으로 집계됩니다.
분류가 빈 행은 위쪽 행 값을 상속하지 않습니다.

### 진행 현황 메모 작성 규칙

메모 앞에 `[월/일]` 을 붙이면 타임라인·무소식 배지·캘린더가 자동으로 동작합니다.

```
[8/12] 1차 시안 공유
[8/18] 피드백 반영본 전달(디자인팀)
```

### 인식하는 상태값

`시작 전` `진행 중` `협의 필요` `확인 요청` `확인 필요` `이전` `잠시 중단` `중단` `완료`

목록에 없는 값을 써도 됩니다 — 자동으로 색이 배정되고 `NEW` 로 표시됩니다.

## 루틴(반복) 업무

매주·매월 반복되는 일은 `M열(반복 주기)`과 `N열(최근 수행일)` 두 칸만 채우면 됩니다.
**다음 예정일 열은 두지 않습니다** — 최근 수행일에 주기를 더해 대시보드가 계산하므로 두 값이 어긋날 일이 없습니다.

| M열 표기 | 의미 |
|---|---|
| `매일` | 매일 |
| `매주 월` · `매주 화,금` | 지정 요일마다 |
| `매월 5일` · `매월 말일` | 매월 특정일 |
| `매분기` | 3개월마다 |
| `매년 3/1` | 매년 특정일 |
| `10일마다` · `2주마다` | N일/N주 간격 |

목록에 없는 표기를 넣어도 루틴으로는 인정되며, 주기를 해석하지 못하면 다음 예정일만 계산하지 않습니다.

**운영 방법** — 루틴을 한 번 처리할 때마다 `N열` 날짜만 오늘로 바꿔 주세요. 다음 예정일이 자동으로 밀립니다.
`N열`이 비어 있으면 **미실행** 으로 표시되어, 한 번도 돌지 않은 루틴을 찾아낼 수 있습니다.

`루틴` 탭에서는 지연·오늘·이번 주·예정·미실행 분류, 다음 14일 날짜별 부하,
캘린더 탭에서는 `루틴 반복 일정` 기준으로 그 달의 모든 반복 발생일을 볼 수 있습니다.

## 날짜 형식

처리예정일자 · 처리일자 · 요청 일자 열은 아래 형식을 인식합니다.

`2026. 8. 15` · `2026-08-15` · `2026/8/15` · `8/15` · `8월 15일`

## 제약

- 브라우저에서 구글시트를 직접 읽으므로 **시트가 링크 공개 상태여야** 합니다.
  비공개 시트를 쓰려면 별도 백엔드나 Apps Script 프록시가 필요합니다.
- 읽기 전용입니다. 대시보드에서 시트를 수정하지 않습니다.
- 브라우저 스토리지를 쓰지 않습니다. 필터 상태는 새로고침 시 초기화됩니다.

## 주의 — 업무 데이터를 커밋하지 마세요

이 저장소에는 데모 데이터만 들어 있습니다.
실제 업무 시트를 연결해 쓰다가 스냅샷을 파일에 박아 넣은 버전을 만들었다면,
**그 파일은 커밋하지 마세요.** `.gitignore` 에 관련 패턴이 등록돼 있습니다.

또한 GitHub Pages 로 배포하면 **저장소가 비공개여도 배포된 사이트는 공개**됩니다.
공개 사이트 URL에 실제 시트 ID를 붙여 공유하는 것은 시트를 공개하는 것과 같습니다.

## 시트 양식 (데모)

`template/업무보드_시트양식_데모.xlsx` — 바로 쓸 수 있는 빈 양식 + 데모 12건입니다.

- **진행현황** 시트: A~L 12개 열, 상태·우선순위 드롭다운, 날짜 서식, 헤더 고정·필터 적용
- **사용법** 시트: 구글시트 업로드 → 링크 공개 → 시트 ID 복사 → `?sheet=` 연결까지 4단계
- **상태값** 시트: 인식하는 상태 9종과 각 상태가 대시보드에서 갖는 의미

노란색 칸(태스크·상태·처리예정일자·진행 현황)이 채우면 기능이 늘어나는 권장 입력 칸이고,
첫 행은 형식을 보여주는 예시 행입니다. 헤더 셀에 마우스를 올리면 작성 규칙 메모가 나옵니다.

사용 순서: 구글 드라이브에 업로드 → **Google 스프레드시트로 열기** → 내용 교체 →
공유를 **링크가 있는 모든 사용자(뷰어)** 로 → 시트 ID를 대시보드 주소에 `?sheet=` 로 붙이기.

## GitHub Pages 배포 (가장 간단)

별도 서비스 없이 깃허브만으로 웹사이트를 띄웁니다.

1. 저장소 → **Settings** → 왼쪽 메뉴 **Pages**
2. Source: **Deploy from a branch**
3. Branch: **main** / 폴더: **/ (root)** → **Save**
4. 1~2분 뒤 상단에 주소가 표시됩니다

| 주소 | 내용 |
|---|---|
| `https://<계정>.github.io/<저장소>/` | 대시보드 (데모 데이터) |
| `https://<계정>.github.io/<저장소>/?sheet=<시트ID>` | 내 시트 연동 |
| `https://<계정>.github.io/<저장소>/INTRO.html` | 소개 페이지 |

`index.html` 이 진입 파일로 들어 있어 루트 주소로 바로 열립니다
(쿼리스트링 `?sheet=...` 도 그대로 전달됩니다). `.nojekyll` 은 깃허브의 Jekyll 처리를 끄는 파일입니다.

> **저장소를 비공개로 두어도 Pages 로 배포된 사이트는 공개됩니다** (GitHub Enterprise 제외).
> 이 저장소에는 데모 데이터만 있으니 사이트 자체는 안전하지만,
> `?sheet=<실제 시트ID>` 가 붙은 주소를 외부에 공유하면 시트를 공개하는 것과 같습니다.
> 접근 제어가 필요하면 Pages 대신 Vercel + Deployment Protection 을 쓰세요.

## Vercel 배포 (선택)

깃허브 저장소를 Vercel에 연결하면 링크로 공유할 수 있습니다. CLI 없이 브라우저에서 끝납니다.

1. [vercel.com/new](https://vercel.com/new) → **Continue with GitHub** 로 로그인
2. 이 저장소를 **Import**
3. Framework Preset은 **Other**, Build Command·Output Directory는 **비워 둔 채** Deploy
   (정적 파일이라 빌드가 없습니다)

`vercel.json` 이 포함돼 있어 배포 후 아래처럼 접속됩니다.

| 주소 | 내용 |
|---|---|
| `https://<프로젝트>.vercel.app/` | 대시보드 (데모 데이터) |
| `https://<프로젝트>.vercel.app/?sheet=<시트ID>` | 내 시트 연동 |
| `https://<프로젝트>.vercel.app/intro` | 소개 페이지 |

이후 `main` 브랜치에 푸시하면 자동으로 재배포됩니다.

> **배포된 주소는 공개입니다.** 검색엔진 노출은 `X-Robots-Tag: noindex` 로 막아 두었지만,
> URL을 아는 사람은 누구나 열 수 있습니다. `?sheet=<실제 시트ID>` 가 붙은 링크를 외부에 공유하면
> 시트를 공개하는 것과 같습니다. 팀 내부용이라면 Vercel 프로젝트 설정에서
> **Deployment Protection**(Vercel Authentication / Password)을 켜 두세요.

## 소개 페이지 두 가지

| 파일 | 성격 | 용도 |
|---|---|---|
| `about.html` | 웹 랜딩 페이지 | 배포된 사이트를 처음 접하는 사람에게 보여주는 소개 페이지. 시트 주소를 붙여넣으면 접속 링크를 만들어 주는 도구가 들어 있습니다. |
| `INTRO.html` | 인쇄용 한 장 요약 | 기능·스펙을 A4 가로 한 장으로 정리한 자료. 보고·첨부용. |

Pages 에서는 `/about.html`, Vercel 에서는 `/about` 으로 열립니다.
